**الحالة:** موافق للواقع الفعلي للمنظومة (المراحل 0 إلى 5)

## 1. مقدمة ونطاق النظام

### 1.1 الغرض
نظام **"ناظم"** هو منظومة رقمية متكاملة لإدارة المعاملات والمراسلات والطلبات الإدارية لشركة نفط الوسط، تستهدف إلغاء التداول الورقي بالكامل، وضمان الشفافية، والسرعة، والتدقيق الأمني الصارم في توجيه البريد الرسمي والطلبات الإدارية ومتابعة مسارات الموافقة والتهميش والتوقيع.

### 1.2 الأركان الأساسية للنظام
1. **الهيكل التنظيمي الهرمي**: إدارة شجرية من 6 مستويات إدارية وتصنيف للكيانات المركزية والفرعية.
2. **إدارة المستخدمين والمصادقة**: نظام حسابات محلي آمن ومستقل مبني على `username` / `password` مشفّر بواسطة `bcrypt` مع دعم الجلسات وتوكينات JWT، وتتبع نشاط المستخدمين.
3. **مصفوفة الصلاحيات وسير العمل (Workflow Engine)**: توجيه آلي وتدريجي للمعاملات بناءً على موقع المستخدم التنظيمي، دور حسابه، وتسلسل خطوات الاعتماد.

## 2. الهيكل التنظيمي (Organizational Hierarchy)

### 2.1 المستويات الإدارية الستة
1. **مدير عام (`general_manager`)**: أعلى سلطة في الشركة (مكتب المدير العام).
2. **معاون (`assistant`)**: معاونو المدير العام (الشؤون الفنية / الشؤون الإدارية).
3. **هيئة (`directorate`)**: الإدارات العامة التخصصية (العمليات، الحفر، المشاريع، الجيولوجيا، المالية، الموارد البشرية، العقود، إلخ).
4. **قسم (`section`)**: الأقسام التخصصية ضمن الهيئات أو المركزية.
5. **شعبة (`division`)**: الشُعب التابعة للأقسام.
6. **وحدة (`unit`)**: أصغر الكيانات الإدارية التابعة للشُعب.

### 2.2 الخصائص التنظيمية
- **الكيانات المركزية (`isCentral`)**: الكيانات المرتبطة مباشرة بالمدير العام أو المعاونين (مثل الهيئة القانونية، التفتيش والرقابة، التخطيط، قسم تكنولوجيا المعلومات، الأمن والحماية، البيئة).
- **أذونات المراسلة الخارجية (`canSendExternalOutgoing`, `canReceiveExternalIncoming`)**: تحديد أي الأقسام مخولة بمخاطبة أو استلام بريد الجهات الخارجية.
- **إدارة الهيكل من لوحة الإعدادات**: دعم كامل لإنشاء وتعديل ونقل وحذف الأقسام وتعيين مدراء الأقسام وتصدير وطباعة الهيكل الشجري.

## 3. إدارة المستخدمين ونظام المصادقة (Authentication & Authorization)

### 3.1 نظام المصادقة المحلي (Local Auth)
- **المصادقة**: مصادقة مستندة إلى اسم المستخدم وكلمة المرور (`username` / `password`) المشفرة بواسطة `bcrypt`.
- **وسائط التوثيق المزدوجة**: دعم مزدوج لكوكيز الجلسات الآمنة (`express-session` مع MemoryStore / connect-pg-simple) وBearer Tokens (JWT) الموقعة برمجياً لتسهيل التكامل مع مختلف العملاء والبيئات السحابية.
- **سياسة كلمات المرور**: دعم فرض تغيير كلمة المرور للمستخدمين الجدد (`mustChangePassword`) مع لوحة تحكم إدارية لإعادة تعيين كلمة المرور فورياً.
- **تتبع نشاط المستخدمين (`Active Users / Online Status`)**: طبقة تتبع مستقلة في الذاكرة تسجل آخر نشاط للمستخدم مع كل طلب API ناجح، وتوفر معرفة فورية لمن هو متصل الآن (`isOnline`) دون أي اعتماد حصري على قاعدة بيانات PostgreSQL خارجية.

### 3.2 أدوار النظام الأربعة الفعالة (The 4 Core Roles)
يحتوي النظام على أربعة أدوار رئيسية محددة ومنضبطة:
1. **مسؤول النظام (`admin`)**: صلاحيات إدارية شاملة لتهيئة النظام، إدارة المستخدمين والأقسام، سجل التدقيق، النسخ الاحتياطي وإعادة الضبط، وتخصيص السمات.
2. **المسؤول / المخول (`officer`)**: مسؤول القسم أو الشعبة أو الهيئة المخول بالتوقيع، التهميش، رفع المعاملات، الإحالة للجهات الفرعية، وإصدار الكتب.
3. **البريد المركزي (`central_mail`)**: دور متخصص باستلام المراسلات الواردة الخارجية، تسجيلها، وإحالتها للموظفين والجهات المخولة باستلام البريد الخارجي (`canReceiveExternalIncoming`) مع الحفاظ على سرية التوجيه الداخلي.
4. **الموظف (`employee`)**: إنشاء مسودات المراسلات الداخلية، متابعة البريد الموجه له، تقديم طلبات الإجازات، ومتابعة سجلاته الشخصية.

## 4. نظام المراسلات والمعاملات (Correspondence Engine)

### 4.1 أنواع المراسلات الأربعة
1. **صادر داخلي (`internal_outgoing`)**: مخاطبات بين الكيانات الداخلية للشركة.
2. **صادر خارجي (`external_outgoing`)**: كتب رسمية موجهة من الشركة لجهات ووزارات خارجية.
3. **وارد داخلي (`internal_incoming`)**: كتب وتقارير مستلمة داخلياً ومحالة للقسم.
4. **وارد خارجي (`external_incoming`)**: كتب واردة من وزارات أو شركات خارجية يتم إدخالها عبر البريد المركزي.

### 4.2 مسار سير المراسلة وحالاتها
- **الحالات**: `draft` → `under_review` → `pending_approval` → `approved` → `issued` → `in_progress` → `completed` → `archived`.
- **أقسام المراسلات الذكية**:
  - **إعداد مراسلة (Compose)**: إنشاء وتحرير نصي غني معقم برمجياً (`isomorphic-dompurify`).
  - **الوارد (Inbox)**: المراسلات الموجهة لقسم أو حساب المستخدم.
  - **بانتظار التوقيع (Pending Signature)**: المعاملات الموجودة حالياً لدى قسم المستخدم والتي تتطلب إجراءً (توقيع، موافقة، إحالة).
  - **المنجزة (Acted / In-Flight)**: المعاملات التي قام قسم المستخدم باتخاذ إجراء عليها ومررها للجهات التالية وما زالت قيد الإنجاز.
  - **الأرشيف والمتابعة (Archive & Follow-up)**: المعاملات الصادرة والمكتملة والمؤرشفة.
- **التسلسل والترقيم التلقائي**: توليد رقم إشاري متسلسل لكل قسم ونوع مراسلة بالصيغة `{deptCode}-{seq}`.
- **التهميش والتوقيعات الإلكترونية**: تهميش المسؤولين مع التوقيع الإلكتروني المعتمد.

## 5. طلبات الإجازات وإدارة الرصيد (Leave Requests & Workflow)

### 5.1 دورة حياة طلب الإجازة (State Machine)
تسلسل موافقات إلزامي ومنضبط عبر المراحل:
$$\text{pending} \longrightarrow \text{approved\_by\_direct} \longrightarrow \text{approved\_by\_section} \longrightarrow \text{approved\_by\_hr} \longrightarrow \text{approved}$$
- **الرفض (`rejected`)**: متاح في أي مرحلة للمسؤول المختص مع تسجيل سبب الرفض وإشعار الموظف.
- **الإلغاء (`cancelled`)**: متاح لصاحب الطلب قبل الاعتماد النهائي أو لمدير النظام.

### 5.2 التحقق من الرصيد والخصم التلقائي
- فحص رصيد الموظف (`leaveBalance`) عند التقديم وعند الاعتماد النهائي.
- الخصم الفعلي والمباشر لعدد الأيام (`daysCount`) من رصيد الموظف عند وصول الطلب إلى الاعتماد النهائي (`approved`).
- توثيق كل حركة في سجل التدقيق (`audit_log`) وإرسال إشعارات فورية عبر النظام (`system_notifications`).

## 6. البنية التقنية ومعايير التشغيل (Technical Architecture)

### 6.1 المكونات التقنية
- **الواجهة الأمامية**: React 18+، TypeScript، Vite، Tailwind CSS، Shadcn/UI، دعم كامل للغة العربية وتخطيط RTL.
- **الواجهة الخلفية**: Node.js / Express.js مع TypeScript و Drizzle ORM.
- **قواعد البيانات المدعومة**:
  - **وضع الإنتاج**: PostgreSQL عبر `pg` و Drizzle.
  - **وضع التطوير/البيئة المضمنة**: SQLite محلي متكامل (`server/sqliteStorage.ts`) مع تهيئة تلقائية للجداول والمؤشرات وضمان التوافق التام بدون الحاجة لإعداد مسبق.
- **الأمان والتعقيم**:
  - تعقيم المحتوى الغني HTML في الخادم والعميل ضد هجمات XSS عبر DOMPurify.
  - تشفير كلمات المرور باستخدام `bcryptjs`.
  - التحقق من الصلاحيات والأدوار (`isAuthenticated`, `requirePasswordChanged`).
- **الاختبارات الآلية**: Vitest (`npx vitest run`) تغطي سلامة تخزين البيانات، التعقيم الأمني، وسير العمل.
